# EcoFlow Worker (free plan)

Existing Worker: nashe-svitlo-ecoflow. Runtime secrets ECOFLOW_ACCESS_KEY and ECOFLOW_SECRET_KEY must already be configured in the Cloudflare dashboard (never build variables or Git).

Connect the existing Worker via Settings → Builds → Connect, choose EpicMan1997/nashe-svitlo, production branch main, root directory cloudflare/ecoflow, build command node --test worker.test.mjs, deploy command npx wrangler deploy. Disable preview builds; if path filters are available include only cloudflare/ecoflow/** so schedule-history commits do not trigger builds. Stay on Workers Free. The SQLite Durable Object provides a single global rate gate and cached snapshot. No cron, no paid services. It initially collects at most once a minute on demand with exponential backoff up to 15 minutes; actual readings may be older upstream. CORS is not authentication; all snapshot data is the same public-safe telemetry contract already published on Pages. No serials, raw quotas or credentials leave the backend. Only two read-only upstream endpoints are used. Existing HMAC station bindings require the original secret key; a new secret may require re-binding. Check /health and compare against actual Pages station data before enabling the frontend. GitHub Pages and its existing fallback are untouched. No live MQTT or 30-second refresh claimed yet.
