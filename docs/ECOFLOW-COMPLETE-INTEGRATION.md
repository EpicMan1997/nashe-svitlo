# Усі EcoFlow в «Наше Світло»: план приватної інтеграції

Оновлено 20.11.2026. Мета: стабільне безплатне зчитування телеметрії всіх сімейних станцій, а пізніше, за окремим рішенням, захищене керування.

## Чому лише Developer API недостатньо

Офіційний API у поточній конфігурації читає DELTA Pro 3 та три DELTA 2, але ці запити нестабільні. DELTA 3 Plus, RIVER 3 Plus Wireless, RIVER 2 і європейський PowerOcean відмовляють у доступі (зокрема 1006). Це обмеження платформи, а не проблема віджетів GitHub Pages.

### Поточна доступність

| Станція | Офіційний Developer API | Кандидат для решти |
|---|---|---|
| DELTA Pro 3 + Smart Extra Battery | Так, один системний SOC | EcoFlow Cloud private MQTT |
| DELTA 2 (3 шт.) + додаткова батарея | Так, але зараз трапляються збої | EcoFlow Cloud private MQTT |
| DELTA 3 Plus | 1006 | EcoFlow Cloud private MQTT / protobuf |
| RIVER 3 Plus Wireless | 1006 | RIVER 3 Plus private MQTT; Wireless-модифікацію треба перевірити |
| RIVER 2 | 1006 | EcoFlow Cloud private MQTT |
| PowerOcean 5 кВт·год | 1006 для типових європейських моделей | EcoFlow Energy Enhanced MQTT; підтримку конкретного інвертора треба перевірити |

Кожен пристрій перевіряємо індивідуально. Наявність коду інтеграції не гарантує роботу певної прошивки або регіону.

## Безкоштовний рекомендований шлях

1. Поставити **Home Assistant** на пристрій, який працює постійно (наявний сервер, NAS, міні-ПК або інший комп'ютер). GitHub Pages не може самостійно тримати приватне MQTT-з'єднання.
2. Через HACS перевірити `tolwi/hassio-ecoflow-cloud` у режимі `private_api`: актуальні інтеграції містять DELTA 3 Plus і RIVER 3 Plus. Для PowerOcean додатково перевірити `shuette42/ecoflow-energy-ha` у режимі `Enhanced`, де є енергетичні стратегії та швидка телеметрія.
3. Налаштувати європейський регіон EcoFlow і ввійти **локально в Home Assistant**. Не передавати пароль EcoFlow, токени, серійні номери чи cookies через чат і не комітити їх у публічний GitHub.
4. Для кожної станції підтвердити: SOC, вхід W, вихід W, власна автономність EcoFlow, час вимірювання, актуальність і підтримувані команди. Зв'язування з локаціями виконувати **приватно** за пристроєм, не за рівнем SOC.
5. Додати невеликий **локальний read-only exporter**, що перетворює перевірену телеметрію на поточний публічний мінімальний контракт `site/ecoflow-snapshot.json`. Не публікувати IP-адреси, серійні номери, логіни та довільний raw MQTT.
6. На першому етапі опубліковувати лише snapshot із приватного gateway через захищений механізм публікації, одночасно залишивши офіційний API резервом. Перевіряти `updatedAt` для **кожної** станції, не поновлювати давні показники новою позначкою часу.
7. Якщо потрібні зміни SOC/потужності за 2–4 секунди, під'єднати шлюз до **окремого захищеного HTTPS потоку/SSE**. Статичний GitHub Pages і GitHub Actions не дають живого стриму без зовнішнього бекенда.
8. Параметри AC/резерву/режиму PowerOcean відкрити для керування **лише після** захищеної авторизації, перевірки допустимих команд, журналу змін і підтверджень. Ніколи не виставляти MQTT credentials або команди у загальнодоступному клієнті.

## Після збоїв 20 листопада

Офіційний publisher тепер розрізняє `rate_limited`, `api_error`, `not_listed`, `invalid_data`, `unsupported`. Санітизований лог відображає лише кількість DELTA 2 у списку/прив'язаних/помилок, без ідентифікаторів. Це допоможе встановити конкретну причину втрати даних перед міграцією.

**Важливо:** частіший workflow (2 хв) може збільшити кількість помилок EcoFlow Developer API. Не скорочувати інтервал до отримання діагностики. Якщо збої частішають, повернутися до 5–10 хв і переходити на MQTT.
