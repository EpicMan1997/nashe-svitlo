# EcoFlow live telemetry: підготовка до Developer API

## Стан зараз

Фронтенд «Наше Світло» використовує read-only адаптер `site/ecoflow-live.js`.
Він вимкнений за замовчуванням у `site/ecoflow-live-config.json`. Жодного
EcoFlow API ключа, серійного номера, пароля, MQTT-з'єднання чи команди у
публічному сайті немає. Поточні значення в режимі «Демо» є зразками.
**Наявність адаптера не означає, що EcoFlow уже підключено.**

GitHub Pages не може зберігати секретні ключі чи підтримувати власний
постійний MQTT-сеанс. Потрібен окремий бекенд, який підключається до
офіційного EcoFlow Developer API і передає на фронтенд **тільки дозволені
для публікації, read-only** поля. Для потоку обрано SSE (EventSource).
Це архітектурне рішення, а не гарантія фіксованої затримки:
потрібні тестування API, MQTT, веб-сервера, мережі та iOS PWA.

Офіційна документація: https://developer-eu.ecoflow.com/us/document/introduction

## Канонічні ключі без серійних номерів

| Локація | Ключ | Модель |
|---|---|---|
| Дача | `dacha:dp3` | DELTA Pro 3 (основна, 4096 Wh) |
| Дача | `dacha:dp3eb` | Smart Extra Battery DELTA Pro 3 (4096 Wh) |
| Дача | `dacha:d3p` | DELTA 3 Plus |
| Дача | `dacha:d2` | DELTA 2 |
| Дача | `dacha:r3pw` | RIVER 3 Plus Wireless |
| Дім | `home:po` | PowerOcean, два 5000 Wh модулі |
| Соловки | `solovky:d2` | DELTA 2 |
| Соловки | `solovky:d2eb` | DELTA 2 Extra Battery |
| Соловки | `solovky:r2` | RIVER 2 |
| Науменки | `naumenky:d2` | DELTA 2 |

**Після видачі доступу:** на бекенді створити приватну таблицю
`{account, serial, deviceModel, canonicalKey}` за списком пристроїв із
EcoFlow. Впізнавати пристрої за фактичним серійним номером, а не за
відображуваною назвою: DELTA 2 є у кількох локаціях. Ніколи не
публікувати цю таблицю у GitHub Pages. Якщо підтримка BMS додаткової
батареї відсутня, її SOC має бути **невідомим** до появи реальних даних.
Для PowerOcean враховувати `moduleSocPercent` лише якщо API повертає
окремі проценти модулів; інакше модулі не отримують вигаданого SOC.

**Важливо:** актуальні локації та фізична наявність кожного пристрою
потребують підтвердження перед увімкненням реального потоку.
Перестановка станцій = зміна лише приватного backend mapping.

## Публічний read-only протокол

`GET /api/ecoflow/snapshot`: повертає останню валідну телеметрію, але
НЕ видає прострочений SOC за актуальний. Заголовки: `Cache-Control:
no-store`, `Access-Control-Allow-Origin` лише на потрібний origin.

`GET /api/ecoflow/events`: постійний SSE потік з типом
`event: telemetry`, без буферизації на reverse proxy; події надсилати
по мірі надходження від EcoFlow MQTT. SSE автоматично перепідключається.
Надсилати heartbeat-коментарі для підтримки з'єднання, але вони **не**
оновлюють позначку свіжості пристрою. Початковий snapshot і
резервне опитування кожні 30 секунд застосовуються тільки якщо gateway
вже налаштовано. При поверненні вкладки з фону snapshot оновлюється.

Приклад повідомлення snapshot/SSE (для одного або кількох ключів):

```json
{
  "version": 1,
  "emittedAt": "2026-11-01T18:00:00+02:00",
  "devices": {
    "dacha:dp3": {
      "updatedAt": "2026-11-01T17:59:59+02:00",
      "socPercent": 73,
      "inputW": 0,
      "outputW": 490,
      "operation": "discharging"
    },
    "dacha:dp3eb": {
      "updatedAt": "2026-11-01T17:59:59+02:00",
      "socPercent": 69,
      "operation": "discharging"
    },
    "home:po": {
      "updatedAt": "2026-11-01T17:59:58+02:00",
      "socPercent": 64,
      "moduleSocPercent": [65, 63],
      "inputW": 120,
      "outputW": 740,
      "operation": "discharging"
    }
  }
}
```

Ці числа суто ілюстративні, не поточні показники користувача.

Вимоги до шлюзу:

- `socPercent`: лише число у діапазоні 0–100, без відсотків у рядку.
- `inputW`, `outputW`: **W**, не Wh і не kW. Значення від 0 до 20000.
- `moduleSocPercent`: відсотки модулів у відомому фізичному порядку.
- `operation`: `charging`, `discharging`, `holding`, `unknown`.
- `updatedAt`: час останнього **вимірювання станції**, не час читання
  JSON або SSE heartbeat. Відхиляти невірні та майбутні часові мітки.
- `emittedAt`: час фактичної відправки з бекенду у ISO 8601 із часовим
  поясом. Відхиляти затримані й переставлені кадри.
- Фрейм може містити зміни одного або багатьох пристроїв. Значення
  незалежних батарей НЕ слід об'єднувати чи копіювати між локаціями.
- За відсутності нової телеметрії понад 30 с показник стає невідомим.
  Інші живі пристрої залишаються видимими. Відсутнє поле ≠ нуль.
- Всі відомості обмежені читанням. **Не додавати endpoints для
  керування, secrets, AC/Reserve, Admin або записи в EcoFlow**.

Публічний клієнт не є захищеним місцем. Вирішіть окремо, які поля
можна віддавати всім відвідувачам. Для приватного моніторингу потрібна
справжня авторизація читання на бекенді, що буде окремим етапом.

## Увімкнення після отримання ключів

1. Уточнити регіон, квоти, доступний список deviceType, підтримку
   DELTA Pro 3, Smart Extra Battery, DELTA 2/3 Plus, RIVER і PowerOcean.
2. Налаштувати EcoFlow MQTT на **сервері**: accessKey/secretKey з
   секретного сховища (не у GitHub); валідна перевірка підпису; TLS,
   повторне підключення, таймаути й rate limits.
3. Мапувати реальні payload-и **після перевірки офіційної схеми
   кожної моделі**, включно зі знаками потужності, одиницями та BMS.
4. Запустити шлюз із snapshot + SSE, журналюванням latency і health.
5. У `site/ecoflow-live-config.json` змінити `enabled` на `true`,
   додати **тільки публічні HTTPS** адреси `snapshotUrl` та `streamUrl`.
   Жодних ключів, токенів або серійних номерів у URL, коді чи чаті.
6. Перевірити відображення всіх чотирьох локацій і ситуації:
   0% заряду; відсутня додаткова батарея; обрив MQTT; iPhone PWA
   у фоні; застаріле значення; розсинхронізовані модулі; відновлення
   після втрати Інтернету. Тільки після цього називати інфу live.

## Репозиторій перейменовано на nashe-svitlo

Актуальний репозиторій: `EpicMan1997/nashe-svitlo`.
Поточна адреса GitHub Pages у налаштуваннях репозиторію:
`https://epicman1997.github.io/nashe-svitlo/`.

Перевіряйте GitHub Actions за новою адресою репозиторію.
Зовнішній планувальник `workflow_dispatch` має викликати:

`https://api.github.com/repos/EpicMan1997/nashe-svitlo/actions/workflows/refresh.yml/dispatches`

Налаштування зовнішнього планувальника, дозволи токена та його прив'язку
до репозиторію треба перевіряти окремо. Репозиторій і UI вже
перейменовані, але старий URL GitHub Pages не отримує автоматичного
redirect: потрібна нова PWA-інсталяція на iPhone. Всі шляхи
`manifest.webmanifest` (`id`, `scope`, `start_url`), service worker
та JS/CSS відносні (`./`), тому після нового деплою вони повинні
працювати під новою адресою.

Перед увімкненням SSE gateway його CORS allowlist та налаштування
origin потрібно створювати **тільки для нової адреси**, не для старого
шляху. При цьому origin для браузера залишається
`https://epicman1997.github.io`; шлях до Pages застосунку змінений.

GitHub офіційно не перенаправляє GitHub Pages project URL після
перейменування репозиторію:
https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository

Якщо URL Deploy Pages в Actions усе ще показує старий шлях, перевірити
`Settings → Pages` та повторно опублікувати workflow. Не вважати
успішний workflow доказом відкриття саме нової URL, доки вона не
перевірена браузером.
